### Notable decisions that were deliberate, not drift

- **Single-target MVP (#20):** Deliberately simplified the scoring denominator to
  one recruiter-curated skill set. The scoring engine still supports multi-ad
  ranking (`rank_candidate` iterates ads); the UI + seed are scoped to one ad for
  the demo. This is a product simplification for the presentation, not an
  architectural constraint.

- **Defer embeddings (#9):** Data-backed: resolution improved 21 %→33 % from
  phrase normalization alone, and the embedding miss category was dominated by
  language/domain issues (not fuzzy-match failures) that embeddings don't fix
  cheaply. Correct call given the evidence; revisit when Czech alias coverage is
  measured.

- **personal_fit retired (#20):** Was a weak lexical proxy (token overlap on free
  text). Removed from the score headline; schema field kept at 0.0 to avoid a
  breaking migration mid-demo. Correct.

## Flags / items to watch

### F1 — Skill resolution at ~33 % (measured, deferred)

`scripts/measure_resolution.py` exists but the current number hasn't been
re-measured since the NSP alias load (#12) and normalization (#9, #10). With
NSP + diacritics fixes the actual rate may be higher. **Run the script** before
deciding on next taxonomy work.

### F2 — Bridge fit rubric covers only `data-analyst`

`level_checklists` has rubric rows for `(data-analyst, junior/medior/senior)`.
Any ad with `domain != data-analyst` returns `bridge_fit = -1.0` (UI: N/A). For
the single-target demo this is fine (fixed by #45 patching the domain). In a
multi-ad expansion, most ads would show N/A bridge fit. Either:
- Seed a minimal rubric for common domains (general, IT, finance), or
- Drop bridge fit from the multi-ad view and show it only where a rubric exists.

### F3 — `_confidence_band` still uses LLM self-confidence

`score.py::_confidence_band` computes `statistics.mean(c.confidence for c in
capabilities)` — the translator's self-reported confidence float. The evidence-
tier reform (#28) correctly moved the TIER signal away from LLM confidence (which
was uniformly "medium") onto structural source_type. But the **band** still uses
the old float. This creates an internal inconsistency: we trust evidence_tier over
LLM confidence for the tier, but trust LLM confidence for the band width.

Fix: derive the band from the distribution of tiers instead (strong-heavy → narrow
band, weak-heavy → wide). The `tier_by_id` dict is already available in
`score_match`. See inline comment in `score.py`.

### F4 — `doloznost_label` "vysoká" threshold is generous

`evidence.py::doloznost_label` returns "vysoká" (high) when `strong * 2 >= n`
i.e. ≥ 50 % of matched skills are strong-evidenced. A candidate with exactly half
strong + half claimed-only gets the top label. The SFIA spirit is that high
attestation should mean a clear majority. Consider raising to `strong * 3 >= n * 2`
(≥ 67 %) to distinguish "mostly strong" from "half and half".

### F5 — `personal_fit` field in DB / models

Schema column + model field are kept at 0.0 "until the next migration cycle"
(PR #20 note). This cycle never explicitly arrived — it should be tracked as a
cleanup item. When a DB migration is next warranted (e.g. a new column), bundle
the `personal_fit` column drop.

### F6 — `bridge_estimate` months scale is arbitrary

`_bridge_fit` uses `max(0.0, 100.0 - (total_months / 24.0) * 100.0)` — a 24-month
linear ceiling. This means a candidate needing 24+ months of bridging scores 0
regardless of how much above 24. The scale was chosen for the data-analyst demo
where junior gaps close in 6–12 months. For senior or niche roles the ceiling
compresses all hard cases together. Acceptable for the demo; document the
assumption explicitly when expanding rubrics.

## Current state assessment

**Concept intact.** The platform does what it says: CV upload → extraction →
ESCO skill translation → coverage scoring vs a recruiter-curated skill set →
ranked candidate list with drill-in + explainability. The student/changer bias is
addressed via evidence tiers (source_type) and the candidate-type classifier.

**Architecture is sound.** The pipeline is thin (13 orchestration steps, all
single-responsibility modules), the scoring is deterministic-first (LLM only for
translation + reasoning), and the human oversight loop (override + audit) meets
GDPR/CJEU counterfactual requirements.

**New directions since the last review:**
- Explainability layer (counterfactual recourse #37, override audit #38) is new
  and architecturally correct.
- Czech-language presentation layer (#46, #47) signals readiness for a Czech
  audience / investor demo.
- Audit threshold slider (#51) is a small but important recruiter UX addition —
  avoids the "everyone passes" problem when all candidates clear 50 %.

**Risks:**
- R1 (skill resolution ≈33 %) — still the biggest quality ceiling.
- R2 (8 LLM calls / applicant) — deferred cost optimization. Acceptable at demo
  scale; needs addressing before > ~100 applicants.
- R3 (single-target scope) — the scoring engine is multi-ad-capable; the demo UI
  isn't. Expansion requires UI work + broader seed.

## Recommendations

Priority order:

1. **Run `measure_resolution.py`** (free, no LLM) — get the current % after
   NSP + normalization. Drives all subsequent taxonomy decisions.

2. **Fix `_confidence_band` (F3)** — switch from LLM confidence float to
   tier-distribution width. Small change, removes internal inconsistency.
   See `score.py` inline TODO.

3. **Raise `doloznost_label` "vysoká" threshold (F4)** — `strong * 3 >= n * 2`
   (67 %) is a defensible SFIA-aligned threshold. Prevents inflated attestation
   labels for mixed-evidence profiles.

4. **Seed a `general / junior` bridge rubric (F2)** — enables bridge fit for
   non-data-analyst ads without touching the scoring code.

5. **Schedule `personal_fit` column removal (F5)** — bundle into the next
   schema migration.

6. **LLM cost optimization** (`perf/llm-cost` branch, deferred) — 8→4 calls per
   applicant. Start before demo traffic increases.
