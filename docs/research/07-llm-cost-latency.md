# Deep-research #7 — LLM cost & latency optimization for the pipeline

**Run:** wf_53437201-d95 · 84 agents (shared across #6–8) · ~32 min · 2026-06-01
**Bottom line:** The single biggest *factual correction* from the verify pass: the "precompute the ad-side calls" win that the first draft ranked #1 **does not exist** — those calls are already off the per-applicant path (see Verification). The real per-applicant LLM hot path is already lean: `extract_profile` → `translate` (think) → `reason` (think), plus a re-translate on submit (~4 live calls), so the deferred "8→4 calls" target in `docs/RISKS.md` is **largely already met** — *count the real calls before claiming savings*. With call-count mostly handled, the remaining levers are **cost-per-call** and **latency**, in this order: (1) **model-tier** the mechanical calls to Haiku 4.5 (3× cheaper, faster) — fully verified; (2) **structured outputs** to kill the `_strip_fences` parse-retry path; (3) **prompt caching** on the two Sonnet `think=True` calls (needs an `llm.py` refactor); (4) **Batches API** for offline seed/CV-gen only; (5) **streaming** for perceived latency.

## Key findings (post-verification)

1. **Precompute is already done — not a win. (REFUTED, 0/3.)** The first draft claimed moving `classify_ad_domain`, `resolve_isco`, `role_specific_questions` to seed time removes ~3 of 8 hot-path calls. Verify in-repo: `classify_ad_domain` **doesn't exist**; `meta/reflect.py:49` is batch observability (Phase 8.5, not per-applicant); ISCO resolution runs in the **seed/ingest scripts** (`resolve_ad_isco`, e.g. `seed_target_demo`) — **not** in `store_ad`, which only copies an `isco_code` already on the `JobAd` — so it's off the per-applicant path either way; `generate_role_questions` is **already** precomputed once-per-ad via `ensure_role_questions`; `detector/classify.py` is **deterministic** (no `call_json`). Nothing left to move.
2. **Model tiering is the biggest real $ lever. (SUPPORTED, 3/3.)** Haiku 4.5 = **$1/$5** per MTok vs Sonnet 4.6 = **$3/$15** (3× cheaper both directions, ~3× cheaper overall). Route the mechanical calls (`extract_profile`, completion-question gen, prefill) to Haiku; keep `translate_capabilities` (`translate.py:62`) + `reason` (`reason.py:63`) — the two `think=True` calls — on Sonnet. Caveat: validate Haiku doesn't degrade **Czech** extraction (already the weak spot) before committing.
3. **Structured outputs remove the parse-retry path. (SUPPORTED core, 2/3.)** Anthropic Structured Outputs (constrained decoding, GA on Sonnet 4.6 / Haiku 4.5 / Opus 4.8, **no pricing surcharge**, schema cached 24h) would obsolete `_strip_fences` (`llm.py:65-71`). Project already uses Pydantic → schemas half-built. **Corrections:** there is **no parse-retry** to remove — `call_json` runs `json.loads` and raises `ValueError` on `JSONDecodeError` (no retry loop, no caller retries), so this is a **robustness** lever (fewer hard failures), not a cost/retry-billing one; the "~5–10% → <0.1%" failure numbers are invented; and refusal (`stop_reason=refusal`) / truncation (`max_tokens`) still return invalid-but-billed output, so it shrinks the malformed-JSON failure class rather than eliminating billed failures.
4. **Token budgets are already sane — don't over-trim. (SUPPORTED, 3/3.)** `config.py` caps thinking at `LLM_THINK_BUDGET=4000` inside `LLM_THINK_MAX_TOKENS=8000` — **note CLAUDE.md says 8192, which is stale; real value is 8000.** `resolve_isco` caps `max_tokens=200`. The real input bloat is the static prompt bodies (`translate_capabilities.md` ~3.1K tokens, `extract_profile.md` ~2.2K tokens) re-sent every call — absorb with caching, not trimming.
5. **Prompt caching needs a refactor, but less than claimed. (Partly corrected, 0/3 as-written.)** Pricing is right (read 0.1×, 5-min write 1.25×, 1-hr write 2×). **Correction:** a `system` block is **not** required — `cache_control` is allowed on user-message blocks too. A refactor *is* still needed because `render_prompt` interpolates variables inline (static-first, variable-last, or zero cache hits); the 1,024-token Sonnet minimum (4,096 on Haiku) was unstated. Only worth it on the two Sonnet `think` calls that clear the floor.
6. **Batches API = offline only. (SUPPORTED, 3/3.)** 50% off input+output (stacks with caching toward ~95%), but async (most <1h, 24h cap) → **cannot** serve the live Streamlit journey. Fits `scripts/seed_target_demo.py` (~40 one-time calls) + CV-generation scripts + any future bulk re-score. Use 1-hr cache TTL inside batch.
7. **Parallelization is latency-only; Haiku speed-up is real but smaller than claimed. (1/3.)** Concurrent calls bill identically — wall-clock only. **Correction:** "Haiku ~3× faster TTFT" is overstated; measured TTFT gap is ~1.5–2×. The bigger perceived-latency win is **streaming** the two slow `think=True` calls into the candidate panel (UI hides reasoning internals anyway).
8. **Stale docstring. (SUPPORTED, 3/3.)** `llm.py:5` still says "calls Claude (Opus 4.8)" / "Opus 4.8 removed the temperature parameter" but `config.py:27` sets `claude-sonnet-4-6`. Config is correct; the docstring is the stale artifact — reconcile before publishing any cost math.

## Concrete recommendations (for us), ranked

- **RANK 1 — model-tier (high impact / low effort):** add a `model=` param to `llm.call_json`; route `extract_profile` + completion-question + prefill to `claude-haiku-4-5`; keep `translate` + `reason` on Sonnet. A/B on the committed demo CVs incl. a Czech one.
- **RANK 2 — structured outputs (high / medium effort):** replace `_strip_fences` with Anthropic Structured Outputs from the existing Pydantic models on all `call_json` sites; no surcharge. **Correction (Codex):** `call_json` does **not** retry on bad JSON today — it runs `json.loads` and raises `ValueError` on `JSONDecodeError` (`llm.py:104-119`), and no caller retries. So the win is **reliability / fewer hard failures**, not "killing billed parse-retries" (there are none) — don't rank it as a cost lever, rank it as a robustness lever.
- **RANK 3 — prompt caching (medium / medium effort):** refactor `call_json` to put each prompt's static body first with `cache_control: ephemeral` (system *or* leading user block) and variable CV/ad text last; 5-min TTL for the per-applicant burst. Only on the two Sonnet `think` calls.
- **RANK 4 — batches (offline / low effort):** route `seed_target_demo.py` + CV-gen scripts through the Message Batches API (flat 50%), 1-hr cache TTL. Never the interactive journey.
- **RANK 5 — streaming (latency only / low effort):** stream the two `think=True` calls into the candidate panel to cut time-to-first-token at zero cost change.
- **Housekeeping:** fix the `llm.py:5` docstring (Opus 4.8 → Sonnet 4.6) and the CLAUDE.md `8192` → `8000`.

## Caveats

- **No live token counts** — `ANTHROPIC_API_KEY` is scrubbed from agent subprocesses; $/applicant figures are derived from prompt-body byte sizes + published rates, not measured `usage.cache_read_input_tokens`. **Verify against real usage before quoting numbers.**
- At demo volume (tens of calls) absolute $ saved is tiny — these matter for scale/unit-economics. Prioritize the cheap, low-risk RANK 1–2 changes.
- Don't merge calls into a mega-schema: >50-field structured schemas degrade quality. Safe merge is extract+classify (but classify is already deterministic, so even that mostly evaporates).
- Validate Haiku on Czech extraction before fully committing the mechanical calls.
