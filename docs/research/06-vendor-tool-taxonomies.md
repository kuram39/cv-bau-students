# Deep-research #6 — vendor-tool skill taxonomies beyond ESCO

**Run:** wf_53437201-d95 · 84 agents (shared across #6–8) · ~32 min · 2026-06-01
**Bottom line:** Don't swap taxonomies — keep the ESCO backbone, fix resolution at the matching layer, and layer one *commercial-safe* free source for emerging tech. The Czech ~33% gap is primarily a **matching-coverage** problem (unused ESCO alternative/hidden Czech labels + no diacritics-strip in `resolve_skill`), not a missing-language one — so the cheapest high-leverage fix is an **embedding/alias fallback over ESCO's own Czech labels**, built in-house, *after re-measuring the gap against `seed.sqlite`*. O*NET (CC BY 4.0, same license family as ESCO) is the only commercial-safe emerging-**tech** source, but its value is narrower than first claimed (see corrections). Lightcast Open Skills is technically the best fit for both gaps but is **non-commercial-only** and its native-Czech tagging sits in a **paid** product. SFIA (a leveling framework, not a tool dictionary) and the closed talent graphs (LinkedIn, Workday, Eightfold, Gloat, SeekOut) are eliminated.

## Key findings (post-verification)

1. **O*NET is the only commercial-safe emerging-tech source** — CC BY 4.0 (same family as ESCO, fits the committed-seed + NOTICES.md attribution model), full bulk download is genuinely friction-free, current version 30.3. Maintains a *Technology Skills* file + 176 "Hot Technologies" (11,500+ occupation linkages) + 2,400+ "In Demand" software linkages across 285 occupations — the discrete named tools (Power BI etc.) ESCO lacks. **Correction:** the *Web Services API* is **gated** (org affiliation + staff approval + 3 binding agreements), not "zero-friction"; only the bulk download is frictionless. English-only / US-SOC / deliberately shallow — complements, doesn't solve, Czech.
2. **The official ESCO↔O*NET crosswalk is occupation-level ONLY** — real, free, downloadable (EU Commission 2022, ML+human). **Correction:** it maps occupations (2997 of 3008 ESCO occs; 11 armed-forces excluded), **not skills**. So it does *not* directly bridge O*NET tech skills into `expected_skills_for_isco()`; using it still requires building a skill-alignment step on top. Lowers the appeal of the "easy O*NET enrichment" path.
3. **Lightcast Open Skills** — ~34k skills (vs ESCO ~13.9k), built bottom-up from postings/resumes. **Corrections:** refresh is **monthly** (not biweekly — their own FAQ); and the **native-Czech tagging is a property of the PAID "Global Skills" extraction product, not the free Open Skills list** (which is English). So Lightcast is *not* a clean free Czech-label source.
4. **Lightcast licensing is a cliff** — Open Terms grant copy/transform "for any purpose **excluding commercial or for-profit**"; commercial use needs a written contract Lightcast "reserves the right to deny at its sole discretion"; API is now "contract basis". **Corrections:** no source says that commercial contract is *free* (drop "no-cost"); the "AI use needs a contract" point is an *inference* that AI = commercial, not stated text. Nonprofits "in support of a public good" can request free full access.
5. **The Czech gap is mostly aliasing, but that's unverified in-repo** — ESCO v1.2 (May 2024) added emerging concepts (35 occs, 42 skills, 196 knowledge, 677 alt labels) and ships 28 languages incl. Czech. **Correction:** whether the *new* v1.2 content was translated to Czech at release is unconfirmed, and "mostly aliasing" is an inference — **re-measure against the actual `seed.sqlite` Czech alt-label coverage before investing.**
6. **Nesta `ojd_daps_skills`** (MIT, ESCoE-funded) maps phrases to ESCO/Lightcast via MiniLM cosine similarity — self-hostable, no API fee, fits the deferred embeddings roadmap. **Correction:** it is **English-only with no documented Czech support**, and is an extract-and-map *job-ad pipeline*, **not a drop-in `resolve_skill` replacement** — so it's a reference design, not a dependency. The diacritics-tolerance-for-Czech claim is unsubstantiated.
7. **Eliminated** — SFIA 9 (147 skills × 7 responsibility levels = a *leveling* framework, won't resolve "Power BI" or "důlní nakladač"; free personal/internal, paid commercial). LinkedIn Skills Graph (~39–41k skills, 26 locales, 374k aliases — ideal aliases but **partner-gated**; *correction:* an API *does* exist, it's just invitation-only, and Czech-locale quality is unverified). Workday/Eightfold/Gloat/SeekOut — closed SaaS, no standalone taxonomy license, no public API.

## Concrete recommendations (for us)

- **RANK 1 (high impact / low effort / zero license risk):** First **measure** the real Czech resolution rate against `seed.sqlite` (write `scripts/measure_resolution.py`). Then ship the two cheap wins: (a) the deferred **diacritics-strip in `resolve_skill`** (the `isco_resolver` already strips; `resolve_skill` doesn't), and (b) pull ESCO's **alternative/hidden Czech labels into `skill_aliases`**. Likely the biggest jump for least work — and it tells you whether embeddings are even needed.
- **RANK 2 (medium / medium effort / commercial-safe):** Only if RANK 1 leaves a real tool-name gap — load O*NET *Technology Skills / Hot Technologies* from the **bulk download** (CC BY 4.0) and hand-map the handful relevant to ISCO 2511 into `expected_skills_for_isco()` as an enrichment-bonus + gap surface. Note the crosswalk is occupation-level, so the skill mapping is manual/curated, not automatic. Add O*NET / US DoL ETA to NOTICES.md.
- **RANK 3 (in-house embeddings, the deferred roadmap item):** Mirror Nesta's *approach* (local sentence-embeddings + cosine over ESCO's Czech label set) rather than adopting their English pipeline. No per-applicant API cost. Do this only if RANK 1 measurement shows lexical+alias resolution still falls short.
- **RANK 4 (don't, yet):** Lightcast — usable free *today* (non-commercial), but document the monetization re-licensing cliff + at-will-revocation clause in `docs/RISKS.md` now. Treat any embedded Lightcast data as borrowed, not owned. SFIA — reserve strictly as an optional IT *leveling* overlay if a seniority axis is ever added; never as a skill-name source.

## Caveats

- Lightcast skill counts vary in their own docs (32k–35k); native-Czech deliverables unconfirmed without the nonprofit grant — verify before building on it.
- O*NET tech list is curated/shallow (176 Hot Technologies) and adds **no** Czech.
- Crosswalk mappings are ML+human approximations at the occupation level; any skill-level bridging introduces noise → cap + surface as a gap, not ground truth.
- The ~33% figure and "mostly aliasing" diagnosis are **inferred, not measured in-repo** — RANK 1's measurement step exists to settle this before engineering.
- Licensing terms change (e.g. SFIA's May 2025 fee increase) — re-check before any contractual/monetization decision.

## Verification (adversarial pass, 3 voters/claim)

The web research over-sold three things the verify pass knocked down: (a) O*NET's API is **not** zero-friction (gated); (b) the ESCO↔O*NET crosswalk is **occupation-only**, so it doesn't auto-bridge skills; (c) Lightcast's native-Czech tagging is **paid**, and Nesta's lib is **English-only** — so neither is a free Czech fix. The corrected takeaway is more conservative and cheaper: fix resolution in-house over ESCO's existing Czech labels, measure first.

**Tie-in:** Lands on the deferred `resolve_skill` diacritics-strip (CLAUDE.md open items) + the Skill-scoring roadmap's embeddings (C) / NSP (D) phases. Concrete next step: write `scripts/measure_resolution.py`, run it on `seed.sqlite`, then ship the diacritics-strip + ESCO-alias load and re-measure — before deciding whether O*NET or in-house embeddings are worth the data-load effort.
