### MVP pivot — PR #20 (2026-05-31)
**Single-target skills-coverage headline.** All CVs scored against one
data-analyst ad. Headline = % coverage of the recruiter-curated target set.
`total == skill_fit`; bridge_fit kept as a secondary "potential" signal.

**Assessment**: deliberate, not scope creep. Multi-ad ranking still exists in
`rank_candidate`; the MVP narrows the demo to be interpretable for an
interview. The scoring is MORE comparable across candidate types (students vs
experienced) than the old 3-axis weighted sum, because coverage % is
denominator-transparent.

**Watch**: if/when the system is demoed as a general multi-job-board platform,
re-enabling multi-target requires only a UI change — the backend handles it.

## Flags

### F1 — Dead config constants (low risk, maintenance debt)
`config.py` contains `WEIGHT_SKILL_FIT`, `WEIGHT_BRIDGE_FIT`,
`WEIGHT_PERSONAL_FIT` (all unused since PR #20) and `ROLE_BONUS_CAP`,
`ROLE_BONUS_PER` (planned enrichment bonus, never wired into `score.py`).
**Fixed in this commit**: clarified annotations on all five.
**Remaining action**: remove WEIGHT_* and ROLE_BONUS_* when the schema
migration that drops `personal_fit` col lands, or when enrichment is wired.

### F2 — Bridge-fit scale was a magic number (low risk)
`_bridge_fit` used hardcoded `24.0` as the denominator (24 months = score 0).
**Fixed in this commit**: extracted to `BRIDGE_FIT_MONTHS_SCALE = 24` in
`config.py`, imported in `score.py`.

### F3 — `analyze_candidate` (legacy one-shot) has no CI path (low risk)
`pipeline.py` still exports the legacy `analyze_candidate` — kept for
back-compat with original tests. The active UI uses the two-pass journey.
No tests exercise the legacy path with the current pipeline.
**Recommendation**: add a smoke test for `analyze_candidate` or deprecate
explicitly; it will silently diverge from the two-pass path over time.

### F4 — RISKS.md Tier-1 items still open
Three un-addressed Tier-1 risks remain:
- R4: No retry-with-backoff on Anthropic rate-limit (HTTP 429)
- R5: Completion loop has no UI multi-turn dialog
- R22: `names_for_ids` per-ad round-trips (partial improvement only)
These are acknowledged in `RISKS.md`. R4 is the highest-priority for any
live traffic: a 429 today surfaces as a crash, not a graceful retry.

### F5 — `counterfactual_lifts` repeats the same % for every missing skill
By design (every missing skill adds 1 to the numerator → same Δ%), but the
UI currently displays the same `(current, new)` pair for up to 5 skills. A
reader sees "add X → 45%→48%; add Y → 45%→48%…" which looks like a bug.
**Recommendation**: display the Δ once (e.g., "Adding any of the skills below
lifts your score from 45% to 48%") then list the skills, rather than
repeating the numbers per skill.
