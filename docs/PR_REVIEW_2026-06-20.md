## Flags / concerns

### F1 — `SourceType` enum grew incrementally across three PRs (design debt)

**Status: fixed in code, risk remains for next extension**

The tier mapping in `evidence.py` (`_TIER` dict) is correct as of #49. But
`SourceType` in `models.py` is a `Literal[...]` string union with no schema
enforcement at the DB layer — invalid values silently fall through to `_TIER.get(…, "weak")`. A future PR adding a new source (e.g., `competition`,
`volunteering`, `military`) will go undetected unless someone updates the tier
dict. Recommendation: add an assertion or `Enum` + validator so unknown source
types surface at test time rather than silently scoring as weak.

**Suggested fix (one file, safe):**
```python
# evidence.py — after the _TIER dict
def evidence_tier(source_type: str | None) -> str:
    tier = _TIER.get(source_type or "", None)
    if tier is None and source_type and source_type not in ("", "other"):
        raise ValueError(f"Unknown source_type: {source_type!r} — add to _TIER")
    return tier or "weak"
```
Or, lighter, just log a warning and default to `"medium"` (defensible for
unknown real-work types) rather than silently `"weak"`.

outside the demo target domain.

If more job ads are added (or the platform is extended), rubrics for at least
`software-developer`, `accountant`, and a generic catch-all would expand the
platform's useful coverage without a major investment.
