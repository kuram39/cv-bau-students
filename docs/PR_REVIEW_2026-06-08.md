## Notable Architectural Shifts (not drift — intentional simplification)

1. **`personal_fit` retired** (#32 confirms): score is now purely criterion-referenced skill coverage (`total == skill_fit`). `bridge_fit` is a secondary "potential" axis. This is the right call for a student platform — personal fit was LLM noise.

2. **Single-target MVP lock-in**: PRs #29, #30, #45 collectively reinforce a single target ad (341, Datový analytik). The corpus search path (`rank_candidate`) still exists in code but is not exercised in the demo. This is correct for MVP but is the main architectural constraint to watch.

3. **Compliance layer** (PRs #28, #37, #38): EU AI Act Art. 14, GDPR Art. 22, CJEU C-203/22, NYC LL144 surface area is now real and deliberate. Counterfactual recourse + human override + bias audit are not gold-plating — they're table stakes for any production HR AI in the EU.

## Flags

### 1. bridge_fit rubric coverage — domain-locked (medium risk)
`level_checklists` only covers `data-analyst`. The fix in #45 patched the demo by setting `domain='data-analyst'` on the target ad. Any new role in a different domain will return `bridge_fit = N/A`. This is honest (by design, per RISKS #9) but limits the platform's generalisability.

**Recommendation**: Add a rubric generation script or at least a documented template for new domains. Without it, every new role requires a manual `level_checklists` CSV extension before bridge_fit works.

### 2. Czech skill resolution — unmeasured (medium risk)
`scripts/measure_resolution.py` was added in #36 but the actual % has never been reported. The deep-research report inferred ~33% resolution for Czech-language CVs. If true, one in three student skills is silently dropped from scoring.

**Recommendation**: Run `measure_resolution.py` against the current seed DB and commit the output as `docs/resolution_baseline.txt`. Gate any further ESCO alias work on this number.

### 3. Audit threshold not persisted (low risk)
PR #51 adds the threshold slider but the value resets on every Streamlit page reload. For a real audit, the selected threshold should be logged alongside the CSV export timestamp.

**Recommendation**: Store `audit_threshold` in `st.session_state` with a default of 50. Optionally log it in the audit CSV header row. Simple one-liner fix.

### 4. `retag_work_evidence.py` is manual-only (low risk)
The backfill script from #49 must be run by hand against existing DBs. Nothing in `ensure_seeded()` or `init_db()` calls it.

**Recommendation**: Either wire it into the migration path (guarded by a column-exists check on the `work` tier count) or document it clearly in `DEPLOY.md` under "Post-migration steps."

### 5. `real_work_years` not in seed for legacy profiles (low risk)
PR #33 adds `CandidateProfile.real_work_years` but legacy profiles (`None`) fall back to `total_work_years`. The seed rebake in #34 happened before #33 landed, so demo candidates may still carry `None`.

**Recommendation**: Verify the seed DB has non-null `real_work_years` for all 6 demo personas. If not, a targeted `UPDATE` + reseed is needed.

In order of impact:

1. **Run `measure_resolution.py`** — this is the single data point that gates the Czech NLP work. If it's > 70%, skip embeddings. If < 50%, fix diacritics + ESCO aliases now.

2. **bridge_fit rubric for ≥1 new domain** — even one more domain (e.g., `software-developer`) proves the rubric pattern is generalisable and de-risks the single-domain lock.

3. **Multi-role demo** — add a second job ad to the demo seed and show `rank_candidate` working for a second role. This proves the architecture is not just single-target and makes the platform more credible in a presentation.

4. **Audit threshold persistence** — trivial fix, high demo polish.
