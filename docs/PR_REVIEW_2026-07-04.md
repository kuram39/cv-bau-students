### New direction worth naming: a "Responsible-AI" layer (#28, #37, #38, #51)

Four PRs this cycle build a coherent second product surface on top of
matching: **evidence transparency → counterfactual recourse ("doložit X →
71%") → human-override + decision log → bias/four-fifths audit with a
tunable threshold.** This is legally well-grounded (GDPR Art. 22,
EU AI Act Art. 13/14/86, EEOC four-fifths) and the PRs are careful to say so
explicitly (bias-audit is framed as *disclosure*, not a pass/fail gate; the
demo collects no protected attributes). It is not scope creep in the sense
of unrelated features (no auth system, no CRM, nothing outside the BAU
pipeline) — it's still operating on the same Match rows.

But it **is a scope expansion** beyond "extract CVs, match to job ads": the
project has grown a governance/compliance module (override UI, audit CSV
export, selection-rate math) that is a distinct concern from matching
quality. Four of this cycle's ~15 feature/fix PRs went here, versus (e.g.)
zero PRs against the still-open Czech-resolution or LLM-cost work. Given
CLAUDE.md explicitly calls `docs/RISKS.md` "the interview answer-key," this
looks like a deliberate choice to build defensible interview-story surface
area — reasonable if that's the actual goal of the exercise, worth
confirming if it isn't.

### Docs-to-code ratio

### F2 — The LLM-cost-reduction stack (#39–#42) has stalled a month unmerged

**Status: known blocker (needs owner's key), but now the oldest open item**

CLAUDE.md's own "Deferred" list names LLM-cost optimization (8→4 calls) as
the "candidate, not started" item and points at `docs/RISKS.md`. In fact the
work **was** done — four stacked, flag-gated, dark-shipped PRs (`Haiku

open since 2026-06-02, over four weeks, because validating them needs a live
`ANTHROPIC_API_KEY` the agent doesn't have. Recommend CLAUDE.md's "Deferred"
section be updated to reflect "code ready, owner validation pending" rather
than "not started," so the next reviewer doesn't re-scope work that's
already sitting in a PR queue.

### F3 — Bias-audit math is disclosure-only; keep it framed that way

**Status: correctly caveated in-repo, flagging so it stays that way**

#38/#51's four-fifths ratio and selection-rate table operate on
`candidate_type` (student/career-changer/experienced), not a protected
class, and the PR bodies are explicit that this is a fairness-comparison
aid, not a legal compliance certification. That distinction is easy to lose
as the feature grows (e.g., #51's threshold slider). Worth a standing rule:
any future audit-feature PR should keep the "not a decision boundary /
disclosure only" language front and center in both code comments and UI
copy, since the four-fifths number *looks* like a formal EEOC test to a
casual reader even though the input distribution here is intentional
(candidate types, not demographics).
