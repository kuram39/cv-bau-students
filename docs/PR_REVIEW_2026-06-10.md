## Concept check

The core assignment — *AI matching platform processing CVs without years of work
history, translating student/graduate/career-changer capabilities into
experienced-equivalent signals, matched against job postings* — is intact.

The pipeline covers:
- **Extraction:** `extract_profile` (personal data, education, work history, skills, languages)
- **Translation:** `translate_capabilities` → ESCO-namespace capabilities with evidence tiers
- **Classification:** `detector` → student / fresh-grad / career-changer / experienced
- **Matching:** 3-axis score (skill_fit + bridge_fit + personal_fit) against job ad
- **Recruiter layer:** skill-picker, audit, override, counterfactual recourse

## Notable evolution threads (PRs #1–#51)

### 1. Model tier (PRs #1 → #3)
Opus 4.8 on launch → Sonnet 4.6 default with `think=True` only on the two
interpretive calls. Correct call: ~40% cheaper, same quality on extraction
workloads, thinking reserved for the quality-sensitive steps.

### 2. Skill resolution quality (PRs #5 → #6 → #8 → #9 → #10 → #28)
Evolved from hand-seeded 50-skill mock → full ESCO v1.2 namespace → LLM
`esco_term` bridging → NSP Czech aliases → diacritics-insensitive fuzzy
matching → evidence tiers replacing coarse LLM confidence. Each step measured
before merging (see RISKS.md Phase C embeddings decision). Good engineering
discipline.

### 3. Single-target MVP (PR #20)
**Intentional product pivot**, not scope creep. The multi-ad `rank_candidate`
path remains in code (with a known prefilter gap documented in RISKS.md), and
the single-target `_score_single_ad` bypass is clearly separated. This is the
right call for a demo with one curated job ad.

### 4. Candidate type classification (PRs #30 → #31 → #33)
`career_changer` detection now uses the target ad's domain, not a
self-stated `target_domains` field that CVs rarely populate. Real-employment
gate added (`real_work_years`, brigáda discount). Edge cases hardened (Codex
P2 pass). This is methodologically important: the student/experienced split
is the platform's key differentiator.

### 5. Transparency + oversight (PRs #37 → #38 → #51)
Counterfactual recourse (what skills close each gap), recruiter override with
note + timestamp, bias-audit with threshold slider. Directly addresses EU AI
Act alignment (research #1 doc). Good proactive posture for a recruitment AI.

## Flags worth monitoring (not blockers)

### F1 — Dead code in `config.py` (stale matcher weights)
```python
# config.py:56-58
WEIGHT_SKILL_FIT = 0.45
WEIGHT_BRIDGE_FIT = 0.35
WEIGHT_PERSONAL_FIT = 0.20  # personal_fit retired; value 0.0 hard-coded
```
The comment says "UNUSED since PR #20" but the constants remain exported.
Any future author importing these will get the wrong mental model.
**Recommendation:** delete the three constants and update the comment block
that references them. One-line change per constant.

### F2 — `personal_fit` retirement is implicit
`personal_fit` is computed (returns `0.0`) but the score formula treats
`total = skill_fit` since PR #20. The dead axis is not surfaced to recruiters
or documented in the UI. If bridge_fit is the only supplementary axis, the
recruiter panel label "personal_fit: n/a" is accurate but unexplained.
**Recommendation:** either remove `personal_fit` from the score struct (clean)
or add a tooltip explaining the axis is intentionally retired in the MVP.

### F3 — Prefilter gap for future multi-ad corpus
Documented in RISKS.md but worth surfacing: `rank_candidate`'s SQL prefilter
does not join `ad_target_skills` (recruiter-curated set). Safe today because
single-target bypasses the prefilter entirely. **Not a bug now — but the
moment a second target ad is added (even for an A/B test), this gap fires.**
The fix is straightforward (union `ad_target_skills` skill_ids into the
prefilter), and should land before any multi-target feature.

### F4 — Audit threshold slider not persisted (PR #51)
The threshold slider in `_render_audit` resets to 50% on every Streamlit
rerun / page refresh. For a demo that's fine; for a recruiter session
working through a shortlist it's friction. A `st.session_state` default or
a DB-stored preference would make it sticky.

### F5 — Bridge months are estimates, not sourced
`bridge_estimate()` sums `bridgeable_in_months` from hand-curated
`level_checklists` (8 domains). For the data-analyst demo this is fine.
The UI shows the number without caveating it as an estimate. Consider
adding "orientační odhad" phrasing near the months figure — important for
recruiter calibration and AI Act transparency.

## Recommendations (priority order)

### R1 — Ship `perf/llm-cost` next (highest ROI, zero quality risk)
The 8→4 call reduction is fully designed (RISKS.md LLM cost section),
non-breaking, and the two changes are independent (defer reasoning + fold
pitch into summary). At demo volume the latency win is small; at investor
demo with 10+ live uploads it matters. This is the obvious next branch.

### R2 — Run `measure_resolution.py` and close the loop
The script exists (PR #36). Run it against the 6 demo CVs and document the
output in RISKS.md R21. That number either validates the current LLM-term
approach or triggers the next taxonomy work. Without it the "resolution is
fine" claim is unverified.

### R3 — Clean up dead `personal_fit` + stale weights (F1, F2)
Three constant deletions + one UI tooltip or label removal. Ten minutes of
work that prevents future confusion. Should be a `chore/` PR.

### R4 — Guard the prefilter gap before any multi-ad work (F3)
Add a failing test or a `# FIXME: prefilter gap` comment at the exact call
site in `rank_candidate`. When multi-ad scoring lands, the test fails and
forces the fix. Prevents the silent miss described in RISKS.md.

### R5 — Add "orientační odhad" caveat to bridge months in UI (F5)
One-line UI string change. Matters for EU AI Act compliance posture and
recruiter trust calibration.
