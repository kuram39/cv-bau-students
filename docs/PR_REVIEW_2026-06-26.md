## Alignment with core assignment

Core assignment: **AI matching platform that processes CVs** (extraction of
personal data, education, work experience, skills, languages) and **matches
candidates to job postings** — specifically students / fresh-graduates /
career-changers who lack years of experience.

### Fully aligned — quality wins

- **#28 Evidence-strength tiers** (🟢 work · 🟡 thesis/project · ⚪ brigada/hobby):
  Replaced a coarse LLM-self-confidence number with a deterministic, auditable tier
  derived from the *source_type* of the evidence. Core quality improvement.

- **#49 Work-evidence tier bug**: Real employment was being scored as "weak"
  because `'work'` wasn't in the tier map. Critical correctness fix — silently
  biased against candidates with actual jobs.

- **#30 + #31 Candidate-type detector**: Career-changer classification now
  fires against the target ad's domain (not the candidate's self-stated
  target_domains, which is usually empty). Fixes the "everyone is experienced"
  regression. Core to the student-vs-experienced promise.

- **#48 Bridge-fit months**: `~N měs.` is graspable; the 0–100 index was not.
  Secondary signal, but now legible to a recruiter.

- **#51 Audit threshold slider**: The hard-coded 50% threshold was saturated in
  the demo — everyone cleared it, making the four-fifths ratio meaningless.
  Slider lets the recruiter find a discriminating cut. Fairness tooling, not
  scope creep.

### Aligned with regulatory/transparency rationale

- **#37 Counterfactual recourse** (`↗️ Doložit X → pokrytí N%`): Zero-LLM,
  deterministic arithmetic from existing `SkillFitDetail` data. GDPR Art. 22 /
  CJEU C-203/22 endorsed form of explanation. Adds recruiter value + regulatory
  coverage. *Acceptable scope addition — low implementation risk.*

- **#38 Human oversight (override + bias-audit)**: Adds `recruiter_override /
  override_note / decision_at` to Match rows + per-type selection-rate audit.
  Satisfies EU AI Act Art. 14 (human-in-the-loop) and gives the recruiter a
  documented override trail. *Acceptable — required for responsible deployment.*

## Flags / concerns

### 1. `personal_fit` retired but schema field kept (⚠️ confusion risk)

`score.py` hardcodes `personal_fit=0.0` since PR #20. The field still exists in
`MatchScore` and `db_models.Match`. This silently inflates a "3-axis scoring"
claim while one axis is always 0. Risk: a future developer re-activates the
field without realising it was retired, or the interviewer asks about it and
the code contradicts the architecture doc.

**Recommendation:** Either remove the field in a schema migration (clean), or
add an explicit deprecation comment at every site that touches it.

### 2. LLM call count still 8 per applicant (⏳ scale blocker)

The `perf/llm-cost` branch documented in RISKS.md as the next deferred item has
not shipped. At Tier 1 (Anthropic RPM cap 50), 9 concurrent uploads trigger
429s. The two calling paths are:
- `run_generic_pass`: extract_profile (#1) + translate (#2)
- `submit_role_specific`: translate (#3) + reason_for_ranking (#4-8)

The `reason_for_ranking` loop is the expansion point — it fires once per
returned ad (up to `top_n`, currently 3 by default in run_generic_pass but
unbounded for the match list). This is the **#1 remaining technical risk**.

**Recommendation:** Cap or batch the `reason` pass first (cheapest win); then
investigate merging extract_profile + translate into a single structured-output
call.

### 3. Role-scoped seed narrows demo breadth (#24)

Shrinking 200k→2k rows was right for boot speed, but it ties the demo to a
single data-analyst target ad. If the owner runs a non-data-analyst demo CV,
the taxonomy coverage drops to ~0. The seed is the demo's safety net.

**Recommendation:** Document this constraint in the demo runbook (CLAUDE.md).
The seed rebuild path is already described — it just needs a note that
`seed_target_demo.py` is ad-specific.

### 4. Completion loop has no UI dialog (⏳ Tier-1 risk)

RISKS.md Tier-1 item #5: when BAU-mandatory fields are missing and the
candidate doesn't fill them, `run_generic_pass` returns `status="needs_completion"`
with an open round — but no multi-turn UI dialog exists. The candidate is
silently stuck. This is the one Tier-1 gap still open after 51 PRs.

**Recommendation:** Add a simple `st.chat_message` loop in `candidate_panel.py`
for the `needs_completion` state. Low complexity (the round object is fully
populated), high impact.

### 5. Czech skill resolution coverage gated on `measure_resolution.py` (🟡)

PR #36 added `scripts/measure_resolution.py` to quantify real ESCO Czech
coverage before investing in embeddings. The measurement hasn't been published
in docs yet — the embeddings/alias-load decision is still open. Meanwhile
Layer-1 resolves ~21% on the 6 demo CVs (RISKS.md §Phase C). If real student
CVs have more Czech free-text, the gap widens.

**Recommendation:** Run `measure_resolution.py` on the committed demo CVs and
add the output to `docs/research/` as a baseline. Gate the embeddings decision
on that number, not on intuition.

## Current state summary

**Concept intact.** The platform correctly implements its core brief:
1. CV → text extraction → structured profile (LLM, ~2 calls)
2. Evidence tiering per source type (deterministic)
3. ESCO skill resolution with diacritics + alias + LLM fallback
4. Skill-fit scoring against recruiter-curated target skills
5. Bridge-fit (months-to-ready) as secondary signal
6. Candidate-type classification relative to target job
7. Recruiter panel with drill-in, override, fairness audit, counterfactual recourse

**New directions introduced (all defensible):**
- Regulatory compliance layer (EU AI Act Art. 14, GDPR Art. 22) — #37, #38
- Evidence auditing (four-fifths ratio) — #51
- Postgres as first-class deployment target — #16, #26, #27, #50
- Czech-first documentation — #46, #47

**Remaining open items (priority order):**
1. LLM cost: 8 calls/applicant → `perf/llm-cost` branch not started
2. Completion-loop UI dialog: `needs_completion` state has no candidate-facing prompt
3. `personal_fit` field: retire cleanly or mark explicitly deprecated
4. Czech resolution baseline: run `measure_resolution.py`, publish output
5. Demo breadth: document role-scoped seed constraint in CLAUDE.md

**No scope drift that contradicts the core concept.** The explainability and
oversight features add governance thickness appropriate for a platform that
makes hiring recommendations — they don't divert the architecture.
