## Flags / concerns

### F1 — Binary seed dependency growing fragile

**Status: risk; document in RISKS.md**

`seed.sqlite.gz` has been rebaked twice (#34, #49) and is now the primary
cold-start source for Cloud/Neon deploys. The binary carries LLM-derived
outputs (translated capabilities, evidence tiers, match scores). If the schema
changes such that SQLAlchemy can't load the gzip (e.g. a column type change,
or a new non-nullable column without a default), the seed becomes unloadable
and recovery requires re-running ~40 LLM calls with the owner's key. There is
no committed "rebuild from scratch" script that doesn't need an API key.

**Recommendation:** add a `scripts/smoke_seed.py` that verifies the seed
can be loaded and the key tables are populated — runs in CI without a key,
catches schema drift before it breaks Cloud deploys.

### F2 — `personal_fit` cleanup still deferred (two reviews old)

**Status: low risk but accumulating**

`personal_fit=0.0` and the TODO comment to delete the schema field after a

— no user-facing change, no migration risk (adding `server_default="0"` to
the column before removal handles existing rows).

### F3 — Bias audit statistically void at 6 demo candidates

**Status: known demo limitation — document clearly**

PR #51 adds a slider and saturation hint, but with 6 candidates (≤2 per type),
the four-fifths ratio is a ratio of tiny integers. A 1-of-1 student "passing"
reads as 100 % selection rate; 0-of-1 reads as 0 %. This is correct behavior
for a transparency *display*, but a presenter unfamiliar with statistical
thresholds may mis-read it as meaningful signal. The `MODEL_CARD.md` should
note the minimum group-size floor (typically N≥30 per group for a meaningful
four-fifths test).

### F4 — Czech resolution still unmeasured with LLM `esco_term` path

**Status: open measurement gap**

`measure_resolution.py` (#36) counts Layer-1 lexical matches and reports 33 %
coverage. The LLM `esco_term` path (translate emits an English ESCO term per
capability; `resolve_skill_esco` maps it to a skill_id) is claimed in research
#7 to cover "~all" cross-lingual/paraphrase phrases. This claim has not been
quantified. A second measurement pass after a keyed `esco_term` re-translate
would confirm whether the effective resolution is 33 % (lexical only) or
materially higher (lexical + LLM). Without this number, the decision to skip
embeddings and NSP hard-skill expansion is data-backed for Layer-1 only.

**Recommendation:** after running `rescore_ad(341)` on Neon with current
prompt, run `measure_resolution.py --include-esco-term` and commit the result
to `docs/RISKS.md` Phase C section.

This has been the top deferred item since `RISKS.md` was written. The 8→4
