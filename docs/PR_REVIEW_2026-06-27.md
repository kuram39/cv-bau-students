### Group assessment

**Core-pipeline correctness fixes (highest signal)**

- **#28 (evidence tiers)** — replaced a meaningless coarse-bucket LLM
  self-confidence label with evidence-source tiers (`work` · `internship` /
  `thesis` / `brigáda` / `claimed`). Directly improves the CV extraction
  quality the assignment depends on. The most consequential change in this window.

- **#49 (work tier bug)** — real employment was landing in `other` →
  "weak" tier because `SourceType` had no `work` value. Markéta Horáková
  (years of actual work) was shown `doloženost: nízká`. Fixed with a new
  `work` source type + a backfill script. Critical correctness fix.

- **#30 (ad-relative classifier)** — `career_changer` now fires correctly.
  Old classifier required a self-stated `target_domains` field (usually
  empty from a CV) → everyone defaulted to `experienced`. New classifier
  compares work history domains to the job ad's domain via fuzzy match.
  The student/career-changer/experienced split is the platform's core
  differentiation — fixing it is mission-critical.

- **#31 (experience gate)** — `brigáda`-only or <2y real work → `student`
  bucket, not `experienced`. Previously, a non-studying 28-year-old with
  only seasonal jobs was misclassified as experienced. Correct.

- **#33 (P2 edge-cases)** — five compounding bugs in evidence + classifier:
  brigáda inflation in `total_work_years`, empty `target_domains` losing
  capabilities, fallback-matched skills showing wrong tier, best-tier-wins
  not applied, pre-rescore matches showing false `nízká`. All pipeline
  correctness issues.

- **#38 (human oversight + audit)** — recruiter override + note stored

### F6 — `WEIGHT_*` constants still dead code after two review cycles

**Status: misleading, carry-forward from F2**

`WEIGHT_SKILL_FIT`, `WEIGHT_BRIDGE_FIT`, `WEIGHT_PERSONAL_FIT` were
annotated as unused in PR #22 but have not been deleted. They still appear
in `config.py:52-54`. A new reader can still misconstrue them as scoring
drivers. Recommendation: delete all three in a `chore/cleanup` PR —
there is no scoring code that reads them and no test that exercises them.
One-liner change, zero risk.

### F7 — `measure_resolution.py` script exists but results not documented

**Status: measurement deferred, decision gated on it**

PR #36 added `scripts/measure_resolution.py` to quantify the real ESCO
resolution rate (Czech diacritics subset + overall). The CLAUDE.md open
items explicitly say this must run before investing in ESCO Czech aliases
or embeddings. The script exists; the measurement does not appear in
`docs/research/` or RISKS.md. This is the blocking prerequisite for the
Czech-resolution roadmap item. Recommendation: owner runs the script on
a real DB and commits the output to `docs/research/measure_resolution_out.txt`.
One CLI invocation.

### F8 — Single-target MVP constraint underdocumented in the UI

**Status: architectural constraint, low risk but worth surfacing**

The app is hard-wired to one job ad (id 341). Switching the target requires
a seed rebuild (`docs/DEPLOY.md §3`). The role-scoped seed (#24) tightened
this constraint. The UI gives no indication to the recruiter that there is
only one active target ad, or that re-scoring against a different ad
requires a redeploy. For a demo this is fine; for a "full platform" claim
it is misleading. Suggestion: add a small `st.info` noting the single-target
demo scope, or at minimum document it in MODEL_CARD.md's Limitations section.

### F9 — `personal_fit=0.0` + schema field still not cleaned up

**Status: low risk, schema field retained unnecessarily**

Carried from F4. The schema column `personal_fit` is set to `0.0` on every
match row and never read. The `WEIGHT_PERSONAL_FIT=0.20` config constant
annotated "UNUSED". Both can be deleted in the same cleanup PR as F6. Not
urgent; not a correctness issue.

### F10 — `retag_work_evidence.py` requires owner execution on Neon

**Status: owner action pending**

PR #49 shipped a deterministic backfill script to fix already-translated
rows where real work was tagged `other`. The PR description notes "owner
runs `python -m scripts.retag_work_evidence --rescore-ad 341`". If this

(e.g. Markéta) still show wrong doloženost. Check that it was executed.
